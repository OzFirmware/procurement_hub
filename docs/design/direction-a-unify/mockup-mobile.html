What is load-bearing here

Card, not reflow. The nine-column grid becomes one card per item at the 700 px breakpoint. Four fields on the face — description, item type, quantity + unit, unit price — and exactly one reveal holding the three optional ones. That is two disclosure levels total, which is the ceiling.

Quantity and unit are one control. Splitting a single value across two mobile fields is a documented failure mode; the composite keeps them on one line and shows the unit as a picker rather than a mystery dropdown reading “pcs”.

The two selects finally have names. Today the item-type select renders blank, is required, and has no label, no placeholder and no touch-reachable hint. Here both selects carry a visible label, a required marker, and a hint button that opens inline.

The total is docked. It used to be a muted span next to “+ Add item”, mid-document. Docking it also drags Submit back on screen, which was previously in a non-sticky header above three cards of form.

Errors point at the field. Item 3 is shown mid-error. Today validation is native required with no :invalid rule anywhere in the stylesheet, so an invalid field looks identical to a valid one until the browser balloon fires — and the server’s own message (“select an item type for R&D”) arrives in a corner toast that auto-dismisses in six seconds, leaving the user to map prose back to a row. Here the border, the message and the control are the same object.

Delete is quiet, duplicate is not. The remove control was a solid red button occupying half a row per item — five items meant the five loudest things on screen were destructive. Real Oizom items differ by one field, so duplicate earns the wider button.
