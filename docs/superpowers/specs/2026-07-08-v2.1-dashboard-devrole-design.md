# Oizom Purchase Tool v2.1 — Advanced Dashboard, Developer Role, Refresh, Branding

**Date:** 2026-07-08
**Status:** Approved by user
**Builds on:** `2026-07-07-purchase-tool-design.md` (v2, shipped)

## Goals

1. Manual refresh button — no tab reload needed.
2. Data-driven dashboard with organized sub-tabs (reference: `previouse.html` prototype).
3. New `developer` role above admin with maintenance powers.
4. Oizom logo branding (asset already in repo).

## 1. Refresh Button

Topbar `↻` button beside the sync chip, visible on every view. Calls
`store.refresh()`; shows a spinning state while `state.loading` is true;
failures surface via the existing error chip. The 60-second auto-poll is
unchanged.

## 2. Dashboard Sub-Tabs

The `#/` view gets an internal tab bar (module state, not routes):
**Overview · Pipeline · Table**. All three render from the already-polled PR
array — zero backend changes.

### Overview (default tab)

- **KPI tiles** (ported from prototype `renderKPIs`, adapted to v2 statuses):
  Total PRs · Pending approval (Submitted) · Unpaid (count + value per
  currency) · In Transit · Received % · Total spend (compact, per currency).
  Clicking a tile applies the matching filter and jumps to the Table tab.
  Received % and Total spend tiles are static (non-clickable).
- **Monthly trend chart**: SVG bar chart of PRs per month keyed on
  `createdAt` (YYYY-MM). Metric switcher: count / spend / unpaid value.
  For money metrics a currency selector appears (amounts are never summed
  across currencies). Clicking a bar opens a month detail panel listing that
  month's PRs (id, item, amount, status), click-through to PR detail.
- **Top-5 breakdowns**: compact spend-by-department and spend-by-vendor bars
  (full versions remain on the Reports page).

### Pipeline

PRs grouped into stage sections: Awaiting Approval (Submitted) → Ready to
Order (Approved) → Moving (Ordered + In Transit, tracking links inline) →
On Hold. Each PR renders as a compact card (id, item, vendor, amount, age in
days); card click → PR detail. Received/Rejected/Cancelled are excluded —
this tab is the daily working queue.

### Table

The existing filterable table, moved under the tab bar unchanged. KPI-tile
clicks pre-populate its filters.

### New pure functions (unit-tested, in `lib/reports.js` or new `lib/metrics.js`)

- `kpis(prs)` → the six tile values
- `monthlyTrend(prs, metric, currency)` → ordered `[ {month, value} ]`
- `pipelineGroups(prs)` → `{awaiting, ready, moving, onHold}` arrays

## 3. Developer Role

Rank above admin: `ROLE_RANK = { viewer:0, requester:1, approver:2, admin:3, developer:4 }`
(both `Code.gs` and the frontend copy in `main.js`).

### Powers (all audit-logged to `Log`)

| Power | Mechanism |
|---|---|
| Hard-delete PRs | New `delete` action, minRole developer; removes the row via `withLock_`; Log row records the deleted PR's snapshot |
| Edit locked fields | In `update`: when caller is developer, editable set expands to all PR columns except `id` (incl. `status`, `requesterEmail`, dates) — bypasses the transition matrix; changes logged field-by-field |
| Maintenance tools | New developer-only actions: `health` (per-tab row counts, sheet names, script version note), `logTail` (last 50 Log rows), `runMigration` (calls `migrateDeptTabs`), `dumpHeaders` (returns tab headers JSON) |
| Hidden accounts | `usersList` omits developer rows unless the caller is a developer; `userSet` rejects granting or revoking `developer` unless the caller is a developer |

### Bootstrap & guards

- First developer is created by editing the `Users` tab directly in the sheet
  (the sheet owner can always do this). Documented in SETUP.md.
- Last-admin lockout guard unchanged (counts `admin` rows only); a developer
  can always repair roles via the sheet or `userSet`.
- Frontend: `Dev` nav tab (developer-only) hosting the maintenance tools +
  a confirm-gated **Delete PR** button on the PR detail view (developer-only).
- UI gating is cosmetic as always — the backend checks are authoritative.

## 4. Oizom Logo

Asset: official logo (474×145 PNG, white wordmark + green icon) already
downloaded → `frontend/public/oizom-logo.png` (Vite copies `public/` to
`dist/`). Used in: dark topbar (replaces text logo, height ~28px) and the
auth gate (above the sign-in box, on the dark gradient). The text fallback
stays as `alt`.

## Error Handling

No new patterns: failed actions toast; refresh failures use the existing
error chip; delete confirms before calling and refreshes after.

## Testing

- Vitest for `kpis`, `monthlyTrend`, `pipelineGroups` (fixtures with
  multi-currency, missing dates, all statuses).
- Existing suites must stay green.
- `.gs` changes: `node --check` via temp `.js` copy.
- E2E additions: developer sees Dev tab / admin does not; admin cannot see
  developer in Users list; delete removes row + Log entry; locked-field edit
  as developer works and is logged; refresh button updates sync chip.

## Non-Goals

- No route changes (sub-tabs are internal state).
- No new spreadsheet tabs or columns.
- No vendor API integrations (still phase 2).
- No charting library — hand-rolled SVG bars like the prototype.
